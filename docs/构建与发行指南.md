# 构建与发行指南

## 本地构建

准备 PowerShell 7.2+ 和 `packaging/windows-lock.json` 中的工具。令 `JAVA_HOME` 指向 Microsoft OpenJDK 21 Windows x64，将指定的 Maven bin 放在 PATH 前面。如需 EXE 安装版，将经哈希核对的 WiX 3.14.1 便携压缩包解压到构建工具目录。JDK 21 的安装器在当前发行工具链调用 `candle.exe`、`light.exe`。 [工具锁](../packaging/windows-lock.json)

```powershell
mvn test
mvn "-Djavafx.integration=true" package
./scripts/build-windows.ps1 -Tests Desktop -WixDirectory 'C:\BuildTools\wix314' -OutputDirectory 'C:\BuildOutput\FileManager-1.0.0'
./scripts/collect-third-party-sources.ps1 -OutputDirectory 'C:\BuildOutput\FileManager-1.0.0'
```

不传 `-WixDirectory` 时生成应用镜像与便携 ZIP。省略 `-OutputDirectory` 时脚本在 `target/windows-release/` 下使用新的构建目录。重复构建可使用新目录。安装器和 ZIP 的运行结果用每次生成的 SHA-256 核对，构建镜像中的 `build-info.json` 记录源码 SHA 与工具版本。

`jdeps` 提取静态模块依赖，另保留语言资源、字符集、管理、ZIP 文件系统和 JNA 所需模块。jpackage 使用相对应用路径加载 Windows x64 JavaFX 模块。主启动器为 GUI，诊断启动器使用控制台。两种发行包均保留 `licenses` 与 `runtime/legal`。

## 安装生命周期复验

在隔离 Windows 账号或临时虚拟机中，构建时加 `-InstallerTestVersion 1.0.1`。测试资产使用相同应用镜像和更高 MSI 版本以验证升级，不属于正式下载。固定升级标识位于工具锁。脚本要求测试账号里还没有该产品，安装目标为指定夹具内的新目录。

```powershell
./scripts/test-windows-installation.ps1 -Setup .\JavaFXFileManager-1.0.0-windows-x64-setup.exe -Upgrade .\JavaFXFileManager-1.0.1-windows-x64-upgrade-test.exe -FixtureDirectory 'C:\Sandbox\FileManager-install-check' -UseMsiPayload
```

自动构建执行默认回归。安装验证提取 EXE 内嵌的 MSI，在 Windows runner 上使用英文含空格的路径，并实际检查快捷方式启动。EXE 的交互界面在桌面验收中验证。两项工作流使用只读仓库权限。 [GitHub Actions](https://github.com/hrao233/Java-/actions) · [验收记录](development/13_独立打包与正式发布/02_验证与人工验收.md)

## 审核与交付

核对用户验收记录、源码 SHA、第三方声明、测试结果和资产哈希。升级验证包和 `build` 中间目录留在构建工作区。只有获得最终发布确认，才在已验收提交建立 `v1.0.0` 标签并发布 ZIP、EXE、校验文件、发行说明和同版本第三方源码附件。发布后重新获取远程标签，再下载附件比对本地 SHA-256。 [发行说明草稿](development/13_独立打包与正式发布/发行说明.md) · [第三方声明](../packaging/THIRD-PARTY-NOTICES.txt)
