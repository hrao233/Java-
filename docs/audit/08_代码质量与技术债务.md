# 08 代码质量与技术债务

现有边界适合继续做单窗口维护。文件写入安全和任务结果归属需要先于跨窗口、标签和双栏设计。这里讨论变更范围和维护成本，文件风险的证据与等级以 [06](06_文件操作与数据安全.md) 为准。

## 五项值得保留的设计

| 设计 | 给维护者带来的价值 | 代价与保留范围 |
| --- | --- | --- |
| 值对象和可直接调用的 I/O 原语 | `Entry/Listing/BrowserItem` 区分底层属性与展示。`LocalFiles` 不要求起窗口即可在隔离目录实测大多数操作。 | 字段可空约定较隐式，值相等不能充当文件身份。保留快照方式，为写入另建对象标记。见 [LocalFiles 记录](../../src/main/java/edu/files/LocalFiles.java#L58-L82)、[BrowserItem](../../src/main/java/edu/files/BrowserItem.java#L6-L37)。 |
| 读成功再提交导航 | 界面路径和列表一起更新，导航失败时旧页及历史仍有效。`AddressBar` 不需要持有文件系统能力。 | 一次性返回有等待，不能局部交付。即使将来允许多项并发，仍要保留“对仍有效的请求才提交”的语义。见 [navigate/request](../../src/main/java/edu/files/FileManagerApp.java#L493-L539)、[AddressBar.openChildren](../../src/main/java/edu/files/AddressBar.java#L254-L267)。 |
| 文件复制暂存和不覆盖默认值 | 目标名通常等数据完成才出现，普通冲突能安全失败。同目录副本有清楚命名。 | 每项发布，批次已有部分成功时不能整体回滚。保留此默认值并改进暂存恢复与失败报告。见 [LocalFiles.copy](../../src/main/java/edu/files/LocalFiles.java#L317-L365)。 |
| 重活移出 FX，图标先回退后回填 | 文件 I/O、图标、图片有不同执行路径。图标的弱引用和缓存避免做大量重复请求而持有废弃控件。 | 读写队列仍会阻塞，缓存需有失效策略。保留后台工作的边界再量化分队列。见 [runTask](../../src/main/java/edu/files/FileManagerApp.java#L1765-L1787)、[SystemIcons](../../src/main/java/edu/files/SystemIcons.java#L75-L117)、[finish](../../src/main/java/edu/files/SystemIcons.java#L163-L179)。 |
| 表格与图块虚拟化并共享选择 | 大列表大部分行不常驻为场景节点，同一选择意图可驱动菜单、快捷键和预览，布局切换不会必然丢选区。 | 需要 `syncing` 处理表格模型和统一选择的重入。以可见行为锁定真实契约后才考虑拆分控件。见 [BrowserView 控件](../../src/main/java/edu/files/BrowserView.java#L160-L175)、[render](../../src/main/java/edu/files/BrowserView.java#L251-L302)、[syncSelection](../../src/main/java/edu/files/BrowserView.java#L1061-L1087)。 |

## 可维护性审查

| 问题 | 影响、证据及优先级 |
| --- | --- |
| 写入结果依赖有副作用的闭包 | `Change` 表达 apply/undo，`PasteItem` 在执行后更新 `copied/changed`，`Outcome.writes` 再读取布尔回调。增加失败类型、记录持久化或并行任务时，测试难从结果判断操作过程。`processChanges` 只接 `IOException`。涉及 P0/P1 的文件风险先解决，其余属于 P2 抽象债。见 [数据结构](../../src/main/java/edu/files/FileManagerApp.java#L88-L103)、[PasteItem](../../src/main/java/edu/files/FileManagerApp.java#L1652-L1689)、[Outcome 处理](../../src/main/java/edu/files/FileManagerApp.java#L1710-L1763)。 |
| 控件状态通过全局变量和字符串命令耦合 | `controls` 以 ID 查找，`fire` 强转 `Button`，新命令需记得在装配、快捷键、上下文菜单及禁用判断同步。没有发现当前 key 的类型不匹配，扩展时可漏更。`searching` 实际意味着“有可取消按钮”，也包含非搜索图库。`cancelNewName` 意义上是任何行内改名。P2。见 [start](../../src/main/java/edu/files/FileManagerApp.java#L180-L225)、[updateControls](../../src/main/java/edu/files/FileManagerApp.java#L1796-L1825)、[控件帮助方法](../../src/main/java/edu/files/FileManagerApp.java#L1931-L1976)、[BrowserView](../../src/main/java/edu/files/BrowserView.java#L308-L335)。 |
| 数据准备与控件耦合 | `BrowserView` 既计算排序、分组，又建表格、图块、首页和图库。`ColumnFilters` 持有对 `BrowserView.Field` 的依赖。现有目录在 `LocalFiles.Listing` 和 FX 都排序，各自用不同规则。先明确底层确定顺序和界面顺序的契约，再决定是否删一层排序。P2。见 [Listing](../../src/main/java/edu/files/LocalFiles.java#L77-L82)、[BrowserView.render/buildLines](../../src/main/java/edu/files/BrowserView.java#L251-L407)、[ColumnFilters](../../src/main/java/edu/files/ColumnFilters.java#L1-L30)。 |
| 错误可见性分散 | `WindowsPlaces.load` 粗略检验字段数，后续多个分支直接取字段并解析，截断行可能使启动失败。`readScriptOutput` 把脚本失败变成空表或部分表。`loadVisits` 没有坏行隔离，若在成功回调抛异常，`updateControls` 可能尚未执行。P2，真实机器重复出现启动阻断时可提高。见 [TSV 解析](../../src/main/java/edu/files/WindowsPlaces.java#L48-L78)、[读取脚本](../../src/main/java/edu/files/WindowsPlaces.java#L131-L150)、[恢复数据](../../src/main/java/edu/files/FileManagerApp.java#L1881-L1897)、[runTask](../../src/main/java/edu/files/FileManagerApp.java#L1765-L1787)。 |
| 多个流程重复装配 | `createItem`、`renameNewItem`、`afterWrite` 都记录父目录修改并重建侧栏/刷新，分别管理状态和 reveal。看似相同的路径依赖不同的条件，提取前先有刷新和选择效果的验证。`pathCrumb` 和 `directoryItem` 都异步读子目录，失败反馈各自定义。P2。见 [新建与命名](../../src/main/java/edu/files/FileManagerApp.java#L1565-L1599)、[afterWrite](../../src/main/java/edu/files/FileManagerApp.java#L1747-L1763)、[面包屑](../../src/main/java/edu/files/FileManagerApp.java#L467-L479)、[目录树](../../src/main/java/edu/files/FileManagerApp.java#L1041-L1059)。 |
| 硬编码的界面与平台假设 | 窗口尺寸、中文文本、时长、搜索和缓存上限在多处。`FOLDERS` 与 `LABELS` 依赖相同索引，图片默认位置用 `fixed().get(3)`。这些值有实际产品语义，建议随相关变更抽成常量或结构，对外保持行为。P2。见 [固定目录](../../src/main/java/edu/files/WindowsPlaces.java#L22-L26)、[恢复图库来源](../../src/main/java/edu/files/FileManagerApp.java#L386-L396)、[图库上限](../../src/main/java/edu/files/FileManagerApp.java#L572-L598)。 |
| 疑似闲置信息与界面承诺 | 首页「活动」列数据区始终为空。磁盘脚本输出 VolumeName，Java 解析 `disk` 时依赖 Shell 名称或根路径回退，未利用该字段。可保留待有用来源的命名，也可以先移除空列。P3。见 [首页数据行](../../src/main/java/edu/files/BrowserView.java#L744-L760)、[磁盘脚本](../../src/main/resources/edu/files/windows-places.ps1#L33-L35)、[磁盘解析](../../src/main/java/edu/files/WindowsPlaces.java#L75-L103)。 |
| 可测试性有基础但缺回归入口 | `FileManagerApp(Preferences)` 已能注入设置。`LocalFiles`、`NewItems.catalog` 和 `ColumnFilters` 可直接测试。文件操作流程、进程、读任务以静态绑定和私有闭包为主，事故夹具不能直接替换执行器或回收器。P1 先为安全路径建立回归，通用测试框架讨论 P2。见 [构造器](../../src/main/java/edu/files/FileManagerApp.java#L163-L169)、[静态 catalog](../../src/main/java/edu/files/NewItems.java#L62-L97)、[11](11_测试与运行验证记录.md)。 |

## 建议的重构范围与取舍

| 方案 | 动机与收益 | 成本和引入问题 | 替代方案及采用时机 |
| --- | --- | --- | --- |
| 提取写入结果与安全检查 | 用显式每项结果替代运行后再读闭包状态。承载真实目标、身份、部分成功、用户中止和可逆原因。为 F01–F05 提供无 UI 测试入口。 | 需要重新定义现有剪切队列、重复副本名和失败结果。若只把代码搬成另一个大类，结果仍不可解释。 | 第一补丁先收窄不安全的撤销。第二步再提取命令输入和结果，保留现有单线程与 UI 回调。 |
| 提取标签浏览状态和请求协调 | 位置、查询、历史和列表集中在一个上下文，能够对结果做归属校验。单标签也可测试导航失败不换历史。 | 多一层状态提交契约，需要统一选区键、视图模式和预览失效方式。 | 先用简单 Java 记录加控制器方法。若有多个反复投影的界面，借用 MVVM 的属性绑定。若主要需求是把控件装配和用例分开，借用 MVC 的控制器分工。 |
| 隔离平台能力与进程执行 | 给回收、Shell 目录及启动器清楚的接口，读取失败反馈可诊断，测试可用 fake 替代系统行为。 | 过早抽象通用 Shell 接口会丢失 Windows 特性，也会让超时规则混用。 | 先对危险或难测的回收、对话框和只读查询分别定义能力与结果，纯 NIO 方法继续用现有实现。 |
| 提取纯展示计算或拆分 BrowserView | 让排序、过滤、分组规则能脱离 JavaFX 写用例。图库排版单独调整时减少对选择/编辑的影响。 | 需要保持字符排序、分组方向、列选择、键盘焦点以及不同节点的可见性。替换布局全量回归成本高。 | 先抽出 `Field` 与纯行计算，有实际变更才拆 `GalleryLayout` 等单一职责。 |
| 维持现在的 UI 组织，只修具体缺陷 | 单窗口、短发布周期、熟悉现有代码时改动成本最低。 | 下一次并行导航或多窗口需求仍会暴露全局 `location/activeTask` 的限制。 | 适用于第一阶段和不涉及多上下文的修补。局部失败可独立提交，是否引入新模式由使用场景决定。 |

检测架构是否变好的简单办法是从一个需求推算变化范围。例如“错误时仍显示前两项已经移动”应该主要改结果类型、协调器和几个断言。若必须同时改多个视图类才可判断已有写入，应优先收紧边界。完整步骤见 [10](10_后续开发路线图.md)。
