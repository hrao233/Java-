# 10 后续开发路线图

下一阶段建议把“移动、改名、回收和撤销必须作用于正确对象”作为交付主题。它比新增视图更容易定义验收，也直接覆盖隔离测试暴露的错误。候选取舍见 [06](06_文件操作与数据安全.md)、[08](08_代码质量与技术债务.md) 和 [09](09_产品体验与功能改进.md)。

## 阶段一 · 修复文件安全并建立回归

**任务。** 先收紧复制目录撤销的范围。为移动、重命名、回收的写入前验证和逆操作记录明确对象身份。将批次结果表达为每项的已完成、无变化、失败或未运行，使部分成功时刷新和撤销都有依据。跨卷非空目录先呈现明确的能力限制，完整跨卷协议单独排期。

可分成两个可审查的提交。第一处修复或停用缺少可靠判断的逆操作。第二处把文件结果、当前作用目标和安全测试提取成小的无 UI 单元。现有视图、PowerShell 启动和磁盘队列可继续使用。

**验收标准**

1. **F01。** 复制两层目录后编辑深层内容。撤销拒绝自动移除或仅回滚安全部分，所有后续用户数据仍可读。未编辑文件的支持行为有独立用例。
2. **F02/F03。** 源或已操作对象同名被换时，不删除或搬动替代品。原位置被占用、目标消失、身份无法确认都返回可读结果。
3. **F04。** 三项批次第一项完成、第二项冲突或消失、第三项未开始。磁盘、界面、撤销记录和剪切余项能对应。预期运行时异常仍保留已写入前缀。
4. **F05/F06。** 两个临时卷上的非空目录按明确策略成功搬移或在变更前拒绝。任一失败分支有确定的源和目标状态。中止与清理只使用新建夹具。
5. **回归。** 继续支持同目录副本名、跨目录无覆盖、大小写改名、普通导航和预览。测试日常创建的汉字、emoji、锁定对象与 Junction。不支持的链接方式显式记录。Java 21 运行和 Maven 构建加入可重复验证。

完成条件是把高危行为改为可证明的安全默认，并让测试扩展而无需点击真实磁盘工具。F01 和 F02 有已有实测对照。见 [11](11_测试与运行验证记录.md)。

## 阶段二 · 让文件工具在日常工作中可依赖

优先改进作业显示、冲突选项、系统剪贴板的复制、目录监听。补齐外部写入和任务取消联动，可先保留单写队列。单项分块复制和自动恢复视具体需求拆开。

验收围绕可解释的结果。任务能在列表和状态栏对齐到真实写入，手动或自动刷新都能重构选择与预览。Windows Explorer 双向复制支持同名和非文件剪贴板。对本地目录做目录事件合并。网络监听不可用时沿用手动刷新并显示状态。性能应记录排队和渲染耗时，在同环境和相同夹具上比较，避免把 P01–P06 热缓存结果当验收上限。见 [07](07_并发与性能分析.md)。

## 阶段三 · 增加独立浏览上下文

先把当前单标签的导航行为写成测试，再引入浏览上下文和请求身份。让切换标签只改变窗口的活动上下文，写入仍由独立作业跟踪。双栏可复用这些边界，是否开发由产品使用判断。

验收要求两个位置的导航栈、查询、筛选、滚动和选区独立。更慢的请求、已关闭的标签和失焦的预览均不能覆盖活跃视图。写入完成能通知受影响位置。见 [05](05_状态管理与生命周期.md)。

## 阶段四 · 按需求扩展

在已稳定的平台接口和作业语义之上评估批量重命名、空间分析、只读 ZIP。每项独立选优先级和样本场景。平台集成补做不同 Windows/JDK 的兼容矩阵。需要发布 EXE 时再补可重建打包文档与依赖版本，避免从现存二进制反推源码发行流程。

以上是调查后的开发建议。本次证据和交付文件以 [审查入口](README.md) 为准。
