# 11 测试与运行验证记录

本次在 Windows 11 25H2（26200.9974）、Oracle JDK `27+35-2325`、Maven 3.10.0、JavaFX 21.0.6 下验证。机器为 Intel Core i7-14650HX，JVM 可见 24 个逻辑处理器，性能样本在 C 盘 NTFS 上。Windows PowerShell `5.1.26100.9818` 供项目调用，脚本静态解析使用 PowerShell 7.6.9。日期为 2026-11-26（UTC+8）。代码基线见 [01](01_项目概况与技术栈.md)。

## 方法与隔离

- 复制当前 `src` 和 `pom.xml` 到专用临时目录。暂停后比较所有 17 个项目源文件与配置的 SHA-256。原工作树是代码引用基准，实际编译、Java 运行和测试在临时副本或以其产物为输入。
- 默认环境的干净编译因 javac 访问 JavaFX 缓存 JAR 失败，异常为 `AccessDeniedException`。同一 JAR 可解包。使用缓存依赖、授权进程环境和新临时副本离线执行 `mvn -o -B -ntp -Dmaven.repo.local=<临时缓存> test`，编译 10 个 Java 文件和复制 5 个资源，输出 `BUILD SUCCESS` 与 `No tests to run`。运行使用这次成功的 `target/classes`。
- 四个 `.ps1` 经 PowerShell AST 解析，语法错误均为 0。解析不验证 COM、C# 动态编译或 Windows API 的语义。U01 完成实际启动流程中的只读系统目录和新建类型读取。
- 交付检查核对了 14 份文档及 383 条本地链接和源码行号。八个 Mermaid 块均由本地 Mermaid 引擎解析，并在独立临时浏览器配置中生成 SVG。
- `SafetyProbe`、`BatchTrashProbe` 从相同包调用真实文件方法，通过反射访问私有 `PasteItem`/`Change`/`processChanges`。单独的 `FxProbe` 用真实 JavaFX Stage、控件和事件，内存 Preferences 与透明窗口。`PerfProbe` 使用 `System.nanoTime`。生成的临时测试源码和 `safety.log`、`batch-trash.log`、`fx.log`、`perf.log` 存放于本机 `%TEMP%\javafx-engineering-audit-xd4ao1j1.qxb`。
- 写入都使用生成的样本。跨卷测试另建空的 D 盘夹具目录并清除该目录，Junction 只指向夹具内部。回收测试传入合成文件或合成目录，用调用结果和原路径存在性断言。未检查回收站内容和恢复流程。启动读取本机只读系统信息，记录不包含实际近期文件路径。

## 可重复的性能夹具

每项单独预热 1 次，同 JVM 计时 5 次。创建文件、目录树和图片发生在相应计时前，P06 则每次创建专用空目标目录再暂存和发布。除图库中使用尺寸读取外，都不含 GUI、队列等待、真实预览解码、SMB、冷缓存或用户文件。

| 编号 | 合成数据和调用 | 最小 / 中位 / 最大 ms | 结果 |
| --- | --- | --- | --- |
| P01 | 平面目录 1,000 个空 `file-N.txt`，`readDirectory` | 25.79 / 27.43 / 30.39 | 1,000 条，无失败 |
| P02 | 平面目录 10,000 个空 `file-N.txt`，`readDirectory` | 254.37 / 264.28 / 273.29 | 10,000 条，无失败 |
| P03 | 深度四层，50 个叶目录每个 200 个空文件，`search("rare-")` | 342.28 / 355.25 / 372.81 | 50 条，遍历全部，无失败 |
| P04 | 同一树，`search("common-")` | 71.24 / 72.73 / 74.62 | 2,000 条并标记上限 |
| P05 | 200 张 160×120 PNG，`images` 后逐项 `imageAspectRatio` | 31.53 / 37.34 / 47.43 | 200 条，宽高比总和约 266.67 |
| P06 | 32 MiB 固定种子随机数据，本地 `LocalFiles.copy` | 8.92 / 9.29 / 11.12 | 每次发布文件 33,554,432 字节 |

复现结构为 `nested/base/g0..g4/d0..d49/leaf`，每个 leaf 一个 `rare-i.txt` 和 199 个 `common-j.txt`。P05 可用 `ImageIO.write(new BufferedImage(160,120,BufferedImage.TYPE_INT_RGB), "png", file)` 生成首张，再复制成不同名称。P06 用 `Random(502)` 写入 32 个 1 MiB 块。P01–P06 可从同包临时 Java 类调用 `LocalFiles`，传 `new LocalFiles.Visibility(false, false)` 与 `() -> false`。对同一次调用分别统计返回条数、上限标记和时长。测试夹具的生成成本与用户界面延迟是另两组指标。见 [07](07_并发与性能分析.md)。

## 手工复核高优先级行为

1. 只在新建临时目录中创建 `source/tree/inner/draft.txt` 和空的 `target`。在应用复制 `tree` 到 `target`。在另一工具中改写 `target/tree/inner/draft.txt`，直接覆写原文件内容。记录目标树在撤销前后是否存在，并确认源文件仍为旧内容。此用例会触发合成树的回收。
2. 在同一夹具建立一个新样本。剪切到目标后，把目标文件改名为不同名字，并写一个同名替代样本。执行撤销，再比较旧位置、替代样本和改名后原对象三者。S09 只使用测试对象。
3. 对跨卷移动，先确认两处都是新建、空的测试目录，再分别测试文件、空目录与非空树。将源、目标和异常一并记录，避免只读状态栏。
4. 批量回收竞态优先采用 S20 的做法，在同包临时测试传入已有样本、预先确定缺失的路径、另一已有样本，调用实际 `processChanges`。这种夹具避免猜测用户在确认框与实际删除之间的时机。
