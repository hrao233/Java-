# 07 并发与性能分析

当前最清楚的并发取舍是串行化文件工作，降低单窗口读写交错和状态竞争，同时让慢任务有机会阻塞后续请求。另一条事实是图标和图片已经从这条队列分离。实际测量覆盖本机临时目录的同步文件操作，下面将其与代码可推得的界面风险区分。原始数字和复现参数见 [11](11_测试与运行验证记录.md)。

## 工作运行在哪条线程

| 执行机制 | 职责与结果回流 | 时序边界 |
| --- | --- | --- |
| JavaFX Application Thread | 交互、列表提交、排序、筛选、分组、布局、按钮、偏好读写、弹窗。`Task.setOn*` 的回调在这里。`Platform.runLater` 用于编辑焦点、列排序、导航后 reveal。 | 慢工作会占用绘制机会。普通 Java NIO 路径校验和拼接基本是 CPU，目录扫描、挂载/属性查询已大多移出。仍需测量整表更新和大量列筛选。见 [App start](../../src/main/java/edu/files/FileManagerApp.java#L171-L240)、[BrowserView.render](../../src/main/java/edu/files/BrowserView.java#L251-L302)、[filter popup](../../src/main/java/edu/files/BrowserView.java#L571-L623)。 |
| `file-manager-disk` 单 daemon Executor | 系统位置加载、主列表、普通搜索、图库尺寸、打开文件、文件写入、文本预览、面包屑和树展开。一条队列，`activeTask` 仅描述一部分前台任务。 | 串行化文件动作。树和面包屑可绕过 `runTask` 入队，慢预览、网络列表或系统对话框可能先占队列，控制条已忙时不一定对应正在执行的项目。见 [disk](../../src/main/java/edu/files/FileManagerApp.java#L105-L109)、[crumb](../../src/main/java/edu/files/FileManagerApp.java#L467-L479)、[tree](../../src/main/java/edu/files/FileManagerApp.java#L1041-L1059)、[preview](../../src/main/java/edu/files/FileManagerApp.java#L1435-L1461)。 |
| `file-manager-icons` 单 daemon Executor | FileSystemView 图标或 namespace 全量脚本第一次读取。请求按键合并，Task 完成后回 FX。Windows JDK 的 Shell 实现可能再调自身线程。 | 不占用磁盘执行器名额。慢原生调用阻塞后续图标。回退可先展示。见 [SystemIcons.request](../../src/main/java/edu/files/SystemIcons.java#L75-L132)、[finish](../../src/main/java/edu/files/SystemIcons.java#L163-L179)。 |
| JavaFX `Image` 后台 | 显示的缩略图、图片预览。后台解码，FX 观察进度、错误与状态。 | 切换预览会移除 ImageView，代码没有作显式 Image 取消。缓存淘汰只移除 Map 中的引用。见 [预览](../../src/main/java/edu/files/FileManagerApp.java#L1416-L1434)、[缩略图](../../src/main/java/edu/files/BrowserView.java#L997-L1020)。 |
| 虚拟线程 | 最近修改扫描保持一个活跃、一个补跑标记。每次 Windows 原生属性单独启动 Task。 | 不占磁盘队列，但可和磁盘任务争用 I/O。属性任务未集中记录，循环打开多个对话框会启动多个子进程。见 [refreshModifiedFolders](../../src/main/java/edu/files/FileManagerApp.java#L1094-L1131)、[showNativeProperties](../../src/main/java/edu/files/FileManagerApp.java#L1512-L1519)。 |

## 阻塞、取消与过期结果

1. **导航和热路径。** 主请求由 `activeTask` 串行，成功提交时一次性更新位置、查询和列表，因此正常导航之间不存在并发结果覆盖。主动取消能把 Task 标记为取消并请求中断，`LocalFiles` 在条目之间抛 `CancellationException`。I/O 已进入文件系统调用时，取消不保证马上释放单线程。新请求可能在旧工作真正退出前进入队列。见 [request](../../src/main/java/edu/files/FileManagerApp.java#L525-L539)、[runTask](../../src/main/java/edu/files/FileManagerApp.java#L1765-L1794)、[checkCancelled](../../src/main/java/edu/files/LocalFiles.java#L447-L451)。
2. **局部结果保护。** 地址子目录结果比较 `popupRevision`。文本预览比较 `previewTask` 的对象。图片错误检查该 ImageView 是否仍在面板。这些防护保护调用方的显示。地址和树的工作仍可能读完，树任务持有自己的旧分支，重建后多是无效 I/O 而非覆盖新树。最近修改允许旧快照短暂回填，随后补跑。见 [地址修订](../../src/main/java/edu/files/AddressBar.java#L254-L298)、[预览回调](../../src/main/java/edu/files/FileManagerApp.java#L1421-L1460)、[目录分支](../../src/main/java/edu/files/FileManagerApp.java#L1041-L1059)。
3. **受控任务和系统等待。** `readScriptOutput` 给 PowerShell 主进程安排 12 秒强制终止，读取 stdout 到 EOF，丢弃 stderr。不检查退出码，所以空、失败和截断可能无法区分。没有对子进程树、管道被继承或响应提前中断给出统一处理。`waitFor` 等原生对话框和部分命令时无总超时，被中断只 `destroy` 主进程。属性页有 C# 内部 15 秒无窗口探测，打开后等窗口结束，跟磁盘格式化/映射对话框等待语义需分别验证。见 [readScriptOutput](../../src/main/java/edu/files/WindowsPlaces.java#L131-L150)、[属性循环](../../src/main/java/edu/files/WindowsPlaces.java#L198-L235)、[waitFor](../../src/main/java/edu/files/WindowsPlaces.java#L369-L380)。
4. **写入关窗。** 普通关闭事件在 `writing` 为真时消费，避免依靠 daemon 线程做最后写入。`stop` 取消读/预览/扫描，关两个执行器，没有持久化写入恢复。不应把任务接受取消等同于写入反转。见 [start/stop](../../src/main/java/edu/files/FileManagerApp.java#L230-L253)、[写入过程](../../src/main/java/edu/files/FileManagerApp.java#L1710-L1745)。
5. **外部变化。** 源码中没有 `WatchService` 或其它文件变更订阅。U08 外部写入合成文件，500 ms 内列表没有更新，点击刷新后出现。焦点事件只触发最近修改，不更新主列表。见 [焦点](../../src/main/java/edu/files/FileManagerApp.java#L230-L232)、[刷新按钮](../../src/main/java/edu/files/FileManagerApp.java#L255-L266)。

## 规模与缓存

| 区域 | 代码可见的成本与失效策略 |
| --- | --- |
| 普通目录和搜索 | `readDirectory` 按项读属性并一次收集，无分页、无普通目录项数上限。递归搜索匹配不多时需要遍历整树。`LocalFiles.Listing` 先排序，FX 的 `render` 再依据用户规则排序，分组时还按组字段排序。`TableView/ListView` 虚拟化可见节点，不省去全量数据排序和行模型。见 [Listing](../../src/main/java/edu/files/LocalFiles.java#L77-L105)、[scan](../../src/main/java/edu/files/LocalFiles.java#L208-L281)、[render/buildLines](../../src/main/java/edu/files/BrowserView.java#L251-L302)。 |
| 图库 | 收集后串行读取各图宽高再交 FX。最多 2,000 张。首批显示要等尺寸阶段，实际缩略解码按可见行触发。改变宽度重新打行。滚动条指示移动时遍历行高求比例。慢图网络/损坏图成本和大量尺寸试读需测量。见 [galleryWork](../../src/main/java/edu/files/FileManagerApp.java#L572-L599)、[gallery rows and scroll hint](../../src/main/java/edu/files/BrowserView.java#L762-L908)。 |
| 系统图标 | LRU 上限 256 张，键为路径或 Shell/namespace、类型和 DPI 像素。不同同类型文件可能重复取。路径键无修改时间，无显式按路径失效，失败回退也可缓存。等待者是弱引用，避免强持有脱离页面的控件。工作队列、pending 键数及 Shell 索引没有对应上限。关闭清缓存并关线程。见 [SystemIcons 字段](../../src/main/java/edu/files/SystemIcons.java#L34-L56)、[graphic/finish](../../src/main/java/edu/files/SystemIcons.java#L75-L93)、[finish/close](../../src/main/java/edu/files/SystemIcons.java#L163-L226)。 |
| 图片缩略图 | LRU 192 张，键包括 URI、模式/高度与修改时间。文件刷新得到新时间可创建新键，旧键留到淘汰。内容变化但时间不变会复用。计数上限不是字节预算，图库请求宽度上限参数为 1,600，实际尺寸视纵横比与解码而定。控件仍持有的图片可能在缓存外。见 [galleryEntry](../../src/main/java/edu/files/BrowserView.java#L823-L839)、[thumbnail](../../src/main/java/edu/files/BrowserView.java#L997-L1020)。 |
| UI 额外耗时 | 打开筛选弹层会按全量源计算桶，首次汉字还会初始化 ICU 转写。图库按宽度重排，选择同步可扫描全行。Windows Preferences 在 FX 被调用。本次未测 FX pulse、GC、峰值内存，也没有大图解码和 DPI 压力样本。见 [openFilter](../../src/main/java/edu/files/BrowserView.java#L571-L598)、[syncTable](../../src/main/java/edu/files/BrowserView.java#L1078-L1087)、[pinyinInitial](../../src/main/java/edu/files/ColumnFilters.java#L91-L99)。 |

## 可以由测量得出的结论

在本机 NTFS 生成合成数据，预热一次、计时五次。1,000 项读取中位 **27.43 ms**，10,000 项 **264.28 ms**。递归 10,000 文件下少量命中 **355.25 ms**。常见关键词因 2,000 项上限提前结束，**72.73 ms**。200 张小 PNG 枚举加尺寸 **37.34 ms**，32 MiB 本地暂存后发布 **9.29 ms**。这些是具体工作、同机热缓存和当次样本的数据，无法代表最慢用户机器、网络盘或端到端 UI 延迟。

在队列中添加第二个工作时，首个读写尚未释放就会等待，这是序列化的结构事实。本次没有在真实慢盘测队列吞吐或崩溃，也没有用生成的图片估算全量内存。后续若为搜索、图库和写入拆分队列，宜先记录入队、开始、I/O 完成、FX 渲染四个时间点，再根据排队和渲染的占比分别选择优化。只让读取并行也需要请求归属与过期检查，写操作继续串行可减少相互覆盖。见 [08](08_代码质量与技术债务.md) 和 [10](10_后续开发路线图.md)。
