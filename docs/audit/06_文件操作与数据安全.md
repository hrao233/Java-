# 06 文件操作与数据安全

本章把一次操作拆成三个检查。**选中的对象是谁，已经写入了什么，逆操作会触碰谁。** 这三件事分别需要核对对象身份、记录每项结果、验证回滚前提。仅保存路径只能回答“名字在哪儿”，同一路径稍后可能对应另一对象。实测编号、环境及未覆盖项见 [11](11_测试与运行验证记录.md)。

## 当前有用的防线

| 情况 | 实际行为与证据 | 验证 |
| --- | --- | --- |
| 同名冲突 | 普通复制到另一目录、移动、重命名先查目标，调用 `Files.move` 时也不带替换选项。同父目录复制生成「 - 副本」「 - 副本 (2)」并重试占用的候选名。同父目录剪切粘贴校验源仍存在后返回无变化。见 [LocalFiles.rename/copy/placeDuplicate](../../src/main/java/edu/files/LocalFiles.java#L307-L368) 和 [move/requireAvailable](../../src/main/java/edu/files/LocalFiles.java#L370-L385)。 | S01–S02 |
| 复制到自身或子目录 | `transferTarget` 取目标目录真实路径，普通源目录也取真实路径比较前缀。拒绝向源目录本身或其后代发布整棵源树。源文件在同一父目录生成副本是另一种条件。见 [transferTarget](../../src/main/java/edu/files/LocalFiles.java#L387-L394)。 | S03、S13 的后代别名 |
| 复制半成品 | 每个项目在目标卷的 `.file-manager-*` 目录内复制，最后搬到正式名。复制异常触发清理，清理异常挂到原异常上。文件复制请求 `COPY_ATTRIBUTES`，目录通过 `createDirectory` 重建，不能承诺复制目录时间、ACL、ADS 或保留硬链接关系。见 [copy](../../src/main/java/edu/files/LocalFiles.java#L317-L346)、[copyTree](../../src/main/java/edu/files/LocalFiles.java#L396-L414)。 | S01、S07、S13 |
| 新建后的逆操作 | `Created.undo` 用创建时间及可用的 `fileKey` 检查对象，文件再比大小和修改时间。目录用非递归 `Files.delete`，仍有子项时失败。该路径会直接删新建对象，需要可靠的前置检查。见 [Created.undo](../../src/main/java/edu/files/NewItems.java#L40-L54)。 | S11。该环境 `fileKey` 返回 `null`。 |
| 回收与系统对话框 | 普通删除需应用确认，使用 `Desktop.moveToTrash`。布尔返回失败时抛出异常，应用没有永久删除的后备操作。原生格式化由 Windows 的 `SHFormatDrive` 显示对话框。见 [trashSelected](../../src/main/java/edu/files/FileManagerApp.java#L1692-L1704)、[LocalFiles.trash](../../src/main/java/edu/files/LocalFiles.java#L300-L305)、[WindowsPlaces.formatDrive](../../src/main/java/edu/files/WindowsPlaces.java#L272-L295)。 | S18、S21 验证回收成功和占用失败。格式化只静读。 |

暂存意味着正式名称通常只在复制完成后出现。当前发布调用没有声明 `ATOMIC_MOVE`，也没有持久化操作日志。文件系统或进程异常下的恢复保证需要单独定义。

## 按影响排序的发现

| 编号与分级 | 触发条件及代码证据 | 影响和已知范围 | 安全复现与候选处理 |
| --- | --- | --- | --- |
| F01 · **P0** · 复制目录的撤销可移走后续写入 | `PasteItem.undo` 只比较目标根的 `LocalFiles.Entry`，其中没有文件身份或后代摘要。覆写深层文件仍可能保持根的路径、类型、大小和修改时间相同，校验通过后回收整棵树。见 [PasteItem.undo](../../src/main/java/edu/files/FileManagerApp.java#L1679-L1689)、[Entry/describe](../../src/main/java/edu/files/LocalFiles.java#L58-L75)、[Entry 构造](../../src/main/java/edu/files/LocalFiles.java#L442-L445)。 | S08 用新内容替换深层文件，根的 `Entry.equals` 仍为真，真实逆操作使目标目录从原位置消失，源中只有旧内容。P0 指后续用户数据遭到非预期移除。实验未验证能否从回收站恢复。普通文件在大小和时间均相同时也可能通过根记录比较，属静态边界。 | 在临时目录复制两层树，更新第二层文件再撤销。首个补丁可禁用目录复制撤销或对有内容的目标拒绝自动回收。要支持完整撤销，定义对象身份与树快照、逐项校验及身份不明时拒绝。校验到写入之间仍有竞争窗口，需纳入契约。 |
| F02 · **P1** · 移动或重命名撤销只依赖路径 | 移动的逆闭包重新拼 `directory.resolve(source.getFileName())`。重命名逆闭包直接使用 `target`。两者都没有存入正向操作完成时的对象身份。原路径有同名冲突时仍会拒绝。见 [renameSelected](../../src/main/java/edu/files/FileManagerApp.java#L1603-L1614)、[PasteItem.undo](../../src/main/java/edu/files/FileManagerApp.java#L1679-L1688)。 | S09 把真实目标移到旁边，再放入同名替代品。撤销搬走替代品，真正移走的对象留在旁边。S10 证实旧地址被占用时拒绝恢复。通常可定位并手动纠正错误移动，影响仍涉及核心写入路径。通过 Junction 的目标路径重指向是同类潜在风险，未实测。 | 在隔离目录按 S09 建立替代品。正向记录实际解析后的路径及可用身份，逆向检查源、目标、路径边界和冲突。有 `fileKey` 时使用它，缺失时明确降级或保守拒绝。 |
| F03 · **P1** · 从列表或内部剪贴板执行时对象可能已换 | `Transfer` 只存 `Path`，确认删除和行内改名也捕获旧的路径快照。真正操作时文件系统按当前路径解析。`copyTree` 按项读取源文件属性和内容，也没有稳定的内容快照。见 [rememberSelection/pasteInto](../../src/main/java/edu/files/FileManagerApp.java#L1620-L1649)、[trashSelected](../../src/main/java/edu/files/FileManagerApp.java#L1692-L1704)、[copyTree](../../src/main/java/edu/files/LocalFiles.java#L396-L414)。 | S12 证实粘贴复制了后放入的同名文件。静态可见同类误操作也能影响剪切、改名和回收。正在被写入的源树可能产生不同时间点的数据集合，发生方式由共享锁和提供者决定。 | 先记录项目，再用另一个操作移开旧项、放入同名临时项，分别检查每个入口。明确“剪贴板绑定对象”或“始终解析最新路径”的产品契约。为会移除或改名的动作加入执行前复验和面向用户的失败说明。 |
| F04 · **P1** · 批次与回收失败分类不完整 | `processChanges` 顺序处理，在首个 `IOException` 停止并返回已执行前缀。遇到运行时异常时 `Task` 整体失败，回调无法接收这个前缀。`Desktop.moveToTrash` 对不存在路径可抛 `IllegalArgumentException`。剪切按已完成数移除前缀，撤销按相同协议消耗前缀。见 [pasteInto](../../src/main/java/edu/files/FileManagerApp.java#L1639-L1649)、[applyChanges/processChanges/afterWrite](../../src/main/java/edu/files/FileManagerApp.java#L1706-L1763)、[runTask](../../src/main/java/edu/files/FileManagerApp.java#L1765-L1787)。 | S04、S05 的普通冲突在第一项成功后中止。S20 使用实际回收操作复现了第一项已移走、第二项缺失抛运行时异常、第三项未处理且无 Outcome。由任务回调可推断此时 UI 可能仅提示失败，仍显示旧列表并保留先前的撤销记录。成功回收没有逆操作，会清空旧撤销记录。 | 隔离同批两项，用可控的底层结果注入让第二项分别抛 IO 异常和预期运行时异常，断言磁盘、界面、剪贴板、撤销四者一致。每项记录成功、无变化、冲突、失败或未开始。捕获可预期的外部错误，保留已写前缀，不把任意内部错误归为文件冲突。 |
| F05 · **P1** · 跨盘非空目录不能移动 | `LocalFiles.move` 调一次 `Files.move`，没有应用层跨卷树搬移协议。见 [move](../../src/main/java/edu/files/LocalFiles.java#L370-L379)。 | S17 在本机两卷实测，文件和目录复制成功，文件移动成功，非空目录移动返回 `DirectoryNotEmptyException`，源内子项保留且目标无目录。单一提供者结果不能外推所有磁盘、共享和驱动器。对于跨卷非原子移动异常需要重新核对两边。 | 只在两个临时卷目录各建合成文件和树。短期准确提示能力限制。长期若支持，设计在目标暂存、验证发布及源端删除三阶段，保留可信副本和可恢复状态，逐阶段注入失败。 |
| F06 · **P1** · 复制阻塞期间缺少取消和进度 | 写入以 `cancellable=false` 运行，`processChanges` 不读取消标记，`copyTree` 的遍历和 `Files.copy` 没有任务取消检查，也没有字节进度。关闭事件在 `writing` 为真时阻止关闭窗口。见 [窗口关闭](../../src/main/java/edu/files/FileManagerApp.java#L233-L238)、[applyChanges](../../src/main/java/edu/files/FileManagerApp.java#L1710-L1722)、[copyTree](../../src/main/java/edu/files/LocalFiles.java#L396-L414)。 | 慢磁盘或网络会延长等待，强制结束可能遗留暂存。S07 只验证共享锁失败时的清理，没有模拟磁盘用尽或强杀。当前 UI 只有忙指示。 | 实现取消时从项目边界起步。若需取消单个大文件，用受控的分块复制，随后仍走暂存发布。区分已经发布的项和清理不完的项。 |
| F07 · **P2** · Junction 和符号链接策略不一致 | 列表与属性按 `NOFOLLOW_LINKS` 读取，`Entry.link` 来自 `isSymbolicLink`。搜索尝试跳过 `isOther` 的目录。复制对 `preVisitDirectory` 的 `isOther` 拒绝，对文件分支则委托 `Files.copy`。目标目录 `toRealPath` 会解析别名。清理遍历没有显式拒绝 Junction。见 [readDirectory](../../src/main/java/edu/files/LocalFiles.java#L87-L107)、[scan](../../src/main/java/edu/files/LocalFiles.java#L208-L280)、[copyTree/deleteStaging](../../src/main/java/edu/files/LocalFiles.java#L387-L433)。 | S13 的 Junction 在 `NOFOLLOW` 下报告 `isDirectory=false、isOther=true`，搜索未进入，复制失败并清理。S14 本机不能创建符号链接，保留链接和链接回收行为待验。静态可见若暂存内容被外部进程改写为重解析点，清理行为取决于提供者。 | 用隔离 Junction 和有权限的符号链接夹具覆盖源、源后代、目标别名、同卷及跨卷。将“导航是否跟随”和“写操作是否跨越重解析点”分开定义，对无法判断的路径给出显式拒绝。 |
| F08 · **P2** · 校验和错误呈现仍有缺口 | `childNamed` 拒绝空白、绝对或多段路径、尾空格和尾句点，设备保留名交给提供者。同名大小写分支使用 `File.renameTo`。复制清理失败附为 suppressed，`showError` 主要呈现主异常。`NewItems.publish` 的 `finally` 清理若抛错可能遮住原异常，也可能发生于发布后。见 [childNamed/rename/copy](../../src/main/java/edu/files/LocalFiles.java#L287-L345)、[NewItems.publish](../../src/main/java/edu/files/NewItems.java#L151-L174)、[showError](../../src/main/java/edu/files/FileManagerApp.java#L1857-L1870)。 | S06 验证中文、emoji、常见非法路径和大小写改名。`NUL.txt` 通过字符串校验，测试未试图写设备名。规范等价 Unicode 拼写不是同一搜索词。S07 实测锁导致复制和移动都失败且没有半成品。ACL、空间不足、紧急中断仅有静态分析。 | 对保留名仅作解析断言。通过失败注入重现清理失败和空间不足，明确用户可见路径与剩余项。属性复制需要独立的 ACL、ADS、时间和权限测试。 |

## Windows 命令的信任边界

- 磁盘工具菜单由 `driveForTools` 与 `supportsDriveTools` 按页面、选中根、盘型和网络标记控制。清理、优化启动 Windows 工具。格式化进入 Windows 对话框，本应用没有再弹一次盘符确认。断开映射先由 `ChoiceDialog` 选择盘符，再用 `WNetCancelConnection2`，`force=false`。映射与格式化取消可以返回而后仍刷新目录。入口标记为系统工具入口，评估风险时要区分唤起对话框与完成破坏性操作。见 [磁盘菜单和工具](../../src/main/java/edu/files/FileManagerApp.java#L797-L855)、[断开映射](../../src/main/java/edu/files/FileManagerApp.java#L1323-L1352)、[Windows 工具](../../src/main/java/edu/files/WindowsPlaces.java#L252-L295)、[网络对话框](../../src/main/java/edu/files/WindowsPlaces.java#L327-L354)。
- `ShellNew Command` 来自本机注册表。脚本跳过 Handler、OptIn 和部分参数占位符。Java 把注册命令与目标目录作为环境变量传入，由 Windows Shell 按注册的程序和参数启动。该分支以打开向导为完成，没有获得创建出的文件路径、落盘确认或撤销记录。值得在 UI 中显示“打开外部向导”及对应发布者/类型信息。见 [ShellNew 枚举](../../src/main/resources/edu/files/windows-new-items.ps1#L79-L101)、[launchNewCommand](../../src/main/java/edu/files/WindowsPlaces.java#L310-L325)、[create](../../src/main/java/edu/files/FileManagerApp.java#L1548-L1563)。
- URL 快捷方式只接受带主机的 HTTP(S)，文件快捷方式先检查目标存在再用 COM 写 `.lnk`。预览和打开可能解析链接，浏览、复制和撤销应各有清楚的策略。原生属性页可以让用户在系统界面更新属性，项目只有启动路径。见 [NewItems.Shortcut](../../src/main/java/edu/files/NewItems.java#L26-L38)、[createShortcut](../../src/main/java/edu/files/NewItems.java#L112-L123)、[showNativeProperties](../../src/main/java/edu/files/FileManagerApp.java#L1490-L1519)。

## 为什么先改撤销

一次写入的正确性和逆操作的安全性是不同承诺。复制可以正确落盘，稍后撤销却可能作用于变化后的树。把曾经的正向结果和撤销前提一起存入操作记录，便能在信息不足时向用户说明哪些项目需要手动处理。最小方案的代价是收窄撤销范围，完整树校验则增加 I/O 和状态成本。两者都比仅比较最外层时间更容易解释和验证。首期验收见 [10](10_后续开发路线图.md)。
