# 05 状态管理与生命周期

窗口生命周期由 `FileManagerApp.start/stop` 管理。多数可变状态由 FX 线程写。后台任务接收当次路径、筛选和集合快照，完成后在 FX 提交。`PasteItem` 是例外，它在磁盘线程生成结果，由完成回调读取。这个模式的要点是明确谁能修改状态，以及哪个结果还有资格提交。见 [成员定义](../../src/main/java/edu/files/FileManagerApp.java#L69-L169)、[任务回调](../../src/main/java/edu/files/FileManagerApp.java#L1765-L1794)。

## 可能产生的不一致

- **路径与页面内容。** `request` 成功后集中提交，避免大部分错页。取消或读取失败时保留上次有效查询与结果，文本输入可能已变成新草稿。没有额外标识区分两者。后退按位置打开，先前的搜索态不随历史还原。见 [search/request](../../src/main/java/edu/files/FileManagerApp.java#L516-L539)、[取消回调](../../src/main/java/edu/files/FileManagerApp.java#L1776-L1787)。
- **选择与视图。** 表格选择和视图集合要双向同步。重读清选区。在保留模式下，`BrowserItem` 的 record 相等性包含属性，路径相同但元数据变化时可能匹配不到。首页折叠文件列表只重组可见行，`ordered/selected` 仍在，可能还允许对已折叠的选择执行操作。见 [render](../../src/main/java/edu/files/BrowserView.java#L251-L305)、[updateHomeRows](../../src/main/java/edu/files/BrowserView.java#L718-L728)、[BrowserItem](../../src/main/java/edu/files/BrowserItem.java#L6-L19)。
- **预览与反复渲染。** `render` 总会调用 `onSelection`，位置不变的排序或筛选也可撤销并重排预览。文本任务身份判断有效，图片错误回调做成员检查。列表再怎么新，当前选择的路径可能被外部替换，详情仍可能显示旧快照。见 [render 末尾](../../src/main/java/edu/files/BrowserView.java#L283-L302)、[refreshInspector](../../src/main/java/edu/files/FileManagerApp.java#L1392-L1461)。
- **近期结果与偏好。** 最近修改计算捕获可见性快照，若期间隐藏设置变化，先完成的扫描可能短时更新旧筛选结果，随后 queued 扫描修正。持久化时受 `Preferences.MAX_VALUE_LENGTH` 限制，长路径或大量书签会跳过装不下的行。读取存在 `Path.of` 与数字转换失败路径，恢复回调没有逐行隔离。见 [refreshModifiedFolders](../../src/main/java/edu/files/FileManagerApp.java#L1094-L1131)、[序列化](../../src/main/java/edu/files/FileManagerApp.java#L1881-L1929)。
- **磁盘与撤销/剪贴板。** 若已经写了若干项才出现非 IO 异常，UI 的三个副本状态可能落后于磁盘。选中路径和逆路径的对象身份另有问题。见 [06 的 F01–F04](06_文件操作与数据安全.md)。

## 多标签页设计推演

先把三类范围写清楚。一个标签拥有其浏览位置、历史、搜索和选区。当标签 A 的慢读取结束，结果最多送到 A，界面只有在 A 活跃时更新显示。窗口持有工具栏、当前标签、窗格和键盘焦点，可以先保留一套 BrowserView，通过当前标签切换快照。应用持有系统目录、用户配置、剪贴板和写入队列，并把变更结果通知影响的路径。

可选方案是在每个标签创建一套控件。它能自然保存滚动和焦点，成本是缓存、节点和额外任务可能成倍增长。复用控件成本较低，但需要显式保存滚动、行内编辑和选择键。两种方案均需给读取携带标签与请求编号。共享写锁仍可限制冲突，不应让切换标签隐含取消已发布的操作。需求优先级与验收见 [09](09_产品体验与功能改进.md) 和 [10](10_后续开发路线图.md)。
