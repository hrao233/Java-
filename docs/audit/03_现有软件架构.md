# 03 现有软件架构

当前是一个由 `FileManagerApp` 编排的单窗口应用。控件把交互以回调交回给应用，应用决定页面、任务和命令能否执行，文件访问及部分 Windows 功能委托给独立类。这个结论来自构造参数、实际调用和状态所有权。源码没有声明 MVC 或 MVVM，部分边界和这两类架构有相似职责。见 [start](../../src/main/java/edu/files/FileManagerApp.java#L171-L225)、[BrowserView 构造](../../src/main/java/edu/files/BrowserView.java#L205-L224)。

[三张 Mermaid 架构图](diagrams/架构与依赖.md) 分别从运行时、类关系和平台依赖展示同一个系统。[04](04_核心功能调用链.md) 按用户动作追踪，[05](05_状态管理与生命周期.md) 列出状态和归属。

## 模块与类的变化影响

“能力”一列包含 Java 的包内入口。这些入口供同包其他类使用，只有 `FileManagerApp` 作为公开的 JavaFX 应用入口。

| 类 | 职责及持有状态 | 能力、调用者与依赖 | 修改影响 |
| --- | --- | --- | --- |
| `FileManagerApp` | 构建 Stage、侧栏、导航和命令。持有位置、查询、历史、每页视图、未提交选择传输、撤销、设置、预览、任务与系统快照。 | JavaFX 调 `start/stop`。`AddressBar` 提交字符串，`BrowserView` 传回选择、打开、排序、菜单请求。调用 `LocalFiles`、`NewItems`、`WindowsPlaces`、`SystemIcons`、`Preferences`。见 [字段与启动](../../src/main/java/edu/files/FileManagerApp.java#L69-L253)、[写入与任务](../../src/main/java/edu/files/FileManagerApp.java#L1620-L1825)。 | 变更导航提交、选择回调或任务完成顺序会同时影响侧栏、地址、预览、按钮和落盘后的刷新。 |
| `BrowserView` | 在详细表与虚拟行之间切换。持有原始和排序/过滤后的列表、选择、锚点、滤镜弹窗、行内编辑、图库布局和缩略图。 | `FileManagerApp` 调 `render/selection/editName/reveal`、选择操作。依赖 `BrowserItem`、`ColumnFilters`、`SystemIcons`、`LocalFiles.isImage`、CSS。用回调表达动作。见 [字段与回调](../../src/main/java/edu/files/BrowserView.java#L150-L224)、[render/editName](../../src/main/java/edu/files/BrowserView.java#L251-L338)、[选择](../../src/main/java/edu/files/BrowserView.java#L1033-L1107)。 | 变更选择恢复、过滤条件或渲染顺序会影响快捷键、右键、预览和文件操作目标。修改图库布局主要影响视觉和滚动行为。 |
| `LocalFiles` | 无实例业务状态。负责文件属性、目录列表、递归搜索、图片分类/尺寸、最近修改归并、打开回收、复制移动和改名。 | `FileManagerApp` 发起磁盘 I/O。`BrowserView` 用其图片扩展名判断，`NewItems` 用其命名与改名。依赖 NIO.2、ImageIO、AWT Desktop。见 [扫描与模型](../../src/main/java/edu/files/LocalFiles.java#L34-L280)、[读写原语](../../src/main/java/edu/files/LocalFiles.java#L283-L452)。 | 影响所有目录/搜索列表，任何写语义变更还影响批量结果和撤销。静态文件方法可直接在临时目录验证。 |
| `BrowserItem` | 表示一个显示条目，包含路径、类型、文件快照或磁盘字段、Shell ID、访问时间。record 本身没有主动 I/O。不同工厂组合允许部分字段为 `null`。 | `FileManagerApp` 和 `WindowsPlaces` 创建，`BrowserView`、`ColumnFilters`、`SystemIcons` 读取。`file` 按 `Entry.directory` 映射 kind，`canModify` 识别 `entry != null`。见 [BrowserItem](../../src/main/java/edu/files/BrowserItem.java#L6-L72)、[canModify](../../src/main/java/edu/files/FileManagerApp.java#L1827-L1831)。 | `equals` 使用快照字段，影响选择保持。更改 Kind/字段可能改变可写判定或图标路径。新增虚拟位置宜先明确能力。 |
| `AddressBar` | 面包屑和地址输入的显示、历史选择、弹窗修订号。保有临时输入、弹窗锚点和视觉 breadcrumbs。 | App 传 `setLocation` 数据及历史/提交回调。子目录由异步回调提供，实际读取在 App，`openChildren` 只接仍有效的结果。见 [构造与数据](../../src/main/java/edu/files/AddressBar.java#L28-L51)、[修订号](../../src/main/java/edu/files/AddressBar.java#L254-L298)。 | 替换 UI 可保持 App 路径解析不变。改变选项选择/失焦事件会影响导航提交与快捷键。 |
| `ColumnFilters` | 按字段分桶和合成选择条件。持有每列已选桶、汉字首字母缓存、惰性 ICU 转写器。 | `BrowserView` 调 `options/includes/select/clear`。入参是 `BrowserItem`、`LocalDate` 和定义于 `BrowserView.Field` 的字段，依赖 ICU4J。见 [字段、判断、分桶](../../src/main/java/edu/files/ColumnFilters.java#L19-L125)。 | 分桶变化影响搜索结果之后的二次显示过滤、分组入口之外的列表数量。若字段定义提取为独立值类型，可使筛选独立于 JavaFX。 |
| `NewItems` | 解释新建类型、从注册值读默认名、独立创建并返回 `Created`。主要状态是该值携带的路径、扩展名和属性戳。 | App 调 `load/create/createShortcut/rename`、保存 `Created.undo`。依赖 NIO、`LocalFiles`、`WindowsPlaces` 及注册表资源。见 [catalog](../../src/main/java/edu/files/NewItems.java#L62-L97)、[创建与发布](../../src/main/java/edu/files/NewItems.java#L99-L174)。 | 修改发布错误或属性记录会影响默认名、行内改名和撤销。向导分支在 App 启动，未使用 `Created`。 |
| `SystemIcons` | 用单独工作线程取图标。持有 LRU、回退图、正在等待某键的弱引用、Shell 项索引和 namespace 图。 | App 的侧栏、面包屑、首页和详情，及 Browser 的可见单元调用 `graphic/namespaceGraphic`。依赖 Swing FileSystemView、Windows 图标脚本及 JavaFX ImageView。App 调 `close`。见 [成员与请求](../../src/main/java/edu/files/SystemIcons.java#L34-L132)、[回填与关闭](../../src/main/java/edu/files/SystemIcons.java#L163-L226)。 | 主要影响初屏、滚动时图标、Windows DPI 与系统图标降级。改变缓存键会影响重复请求和显示时效。 |
| `WindowsPlaces` | 适配 Windows 位置数据与原生动作。主要为静态方法和不可变 `Places` 快照，系统状态来自注册表、Shell、文件系统。 | App 调 `load/indexedModifiedItems` 和 Windows 动作。`NewItems`、`SystemIcons` 共用脚本驱动。`Places` 又装载 `BrowserItem`。见 [系统快照](../../src/main/java/edu/files/WindowsPlaces.java#L22-L115)、[脚本驱动](../../src/main/java/edu/files/WindowsPlaces.java#L118-L160)、[原生命令](../../src/main/java/edu/files/WindowsPlaces.java#L252-L379)。 | 修改 TSV 或退出处理影响启动、新建菜单、快速访问、系统图标。原生命令和实体文件操作可分别验证。 |
| `UiGlyph` | 将工具栏、菜单和地址栏语义符号转成 JavaFX `Label`，选 Windows 字体或字符回退。 | `FileManagerApp`、`AddressBar`、`BrowserView` 调 `graphic`。依赖字体列表与 CSS。见 [UiGlyph](../../src/main/java/edu/files/UiGlyph.java#L6-L35)。 | 影响视觉、字体回退和部分控件提示外观，通常不涉及路径及写入。 |

## 数据和事件怎样到达磁盘

1. 界面事件在 JavaFX Application Thread 进入 `FileManagerApp`，例如 `BrowserView.onOpen` 调 `open`。
2. App 选择 `Location` 和对应 `Work<Listing>`，将所需变量取快照。`runTask` 设为活跃任务，更新按钮并入队。文件目录由 `LocalFiles` 在磁盘线程读出 `Entry`，随后转换为 `BrowserItem`。
3. 成功回调回到 FX 线程提交 `location/activeQuery/listing`，更新地址和侧栏，再 `render` 建立展示行。选择变化又触发 App 更新按钮及预览。失败在原页面出错，导航历史在成功后才推进。
4. 写入共享同一个任务入口，但先建立 `Change` 列表。每个正向动作和逆向动作以闭包在同一位置关联，`Outcome` 决定刷新、剪贴板和撤销。系统图标、Shell 属性、最近修改另有执行路径。

参见 [request](../../src/main/java/edu/files/FileManagerApp.java#L525-L565)、[渲染适配](../../src/main/java/edu/files/FileManagerApp.java#L648-L677)、[顺序写入](../../src/main/java/edu/files/FileManagerApp.java#L1710-L1788)。

## 耦合如何随需求增长

- **App 的主要风险在共享状态的完成顺序。** 菜单禁用、历史提交、任务忙状态和写完后的刷新由同一对象维持。单窗口时这能减少交接，增加标签时容易让后台任务使用完成时的全局 `location` 或 `undo`。例如 `afterWrite` 用当时的 `location/activeQuery` 发起重读，当前可依赖导航门控。允许切标签后便要明确结果归属。见 [afterWrite/runTask](../../src/main/java/edu/files/FileManagerApp.java#L1747-L1787)。
- **BrowserView 的复杂点是跨视图选择契约。** 表格使用 JavaFX 选择模型，图标使用自管集合，`syncing` 防止反向监听重入。排序、分组、筛选、重绘及选择都经过 `render`，同时触发 App 的预览。若将八种模式拆为独立实现，还需要一个跨模式保持焦点和选择的约束。见 [render](../../src/main/java/edu/files/BrowserView.java#L251-L302)、[syncSelection](../../src/main/java/edu/files/BrowserView.java#L1061-L1087)。
- **有可见边界，也有反向依赖。** 回调使 AddressBar 不认识磁盘，图标不占磁盘线程。`ColumnFilters` 却引用控件类内的字段枚举，`WindowsPlaces` 产出展示模型，`SystemIcons` 借 WindowsPlaces 跑脚本。将来若只测试排序或换平台，这些依赖需要隔离。只有当前一个实现时，可以从提取字段和值开始。见 [ColumnFilters imports](../../src/main/java/edu/files/ColumnFilters.java#L1-L8)、[WindowsPlaces.Places](../../src/main/java/edu/files/WindowsPlaces.java#L28-L32)、[SystemIcons.loadNamespaceIcons](../../src/main/java/edu/files/SystemIcons.java#L118-L132)。

当前边界能支持范围明确的修正。操作结果、导航上下文和平台能力适合先按具体问题抽离。全量 MVC/MVVM、每个控件单独抽象和多执行器并不自然解决文件身份与回滚问题。方案成本和退出条件见 [08](08_代码质量与技术债务.md)。
