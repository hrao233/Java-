# 04 性能与回归验证

环境为 Windows 11 25H2 x64（`26200.9974`）、本地 NTFS、Intel Core i7-14650HX、Microsoft OpenJDK `21.0.13.0.2+1-LTS`、Maven 3.10.0 和 JavaFX 21.0.6。JUnit 文件操作使用单独的 `@TempDir` 夹具，桌面测试用内存 Preferences。测试结束后已检查 JUnit 夹具目录完成清理。真实回收站、网络驱动器断开和格式化均未执行。

| JDK 21 执行 | 发现 | 通过 | 跳过 | 失败或错误 |
| --- | ---: | ---: | ---: | ---: |
| 阶段 2.1 基线 `mvn test` | 32 | 31 | 1 | 0 |
| 阶段 2.2 `mvn test` | 55 | 53 | 2 | 0 |
| 阶段 2.2 `mvn '-Djavafx.integration=true' package` | 55 | 54 | 1 | 0 |

默认的两个跳过项分别是需显式开启的 JavaFX 桌面用例，以及只在 NIO 提供者公开稳定对象键时运行的阶段 2.1 用例。本机两次运行都缺少后者所需的 `fileKey()`。开启桌面用例后通过 54 项，打包生成 `target/javafx-file-manager-1.0.0.jar`。JavaFX 类路径启动发出了 unnamed module 警告。一次关闭时，AWT 图标线程还报告了中断，界面断言与 Maven 构建均通过。[既有测试](../../../src/test/java/edu/files/FileSafetyTest.java) · [桌面集成测试](../../../src/test/java/edu/files/JavaFxFileOperationsTest.java)

- **原生 API 与适配器共 22 项。** 稳定文件 ID、等名等内容替代、父目录替代、硬链接、Junction、源文件共享权限、目标文件夹 ACL、中文和 emoji、大小写、无覆盖提交、句柄释放、文件和深层目录修改后撤回，以及无身份时的路径降级均有断言。在受控竞争点，另一线程不能换走已打开的对象或上级目录，但能抢先创建目标。原生提交随后拒绝覆盖。另有受控未知结果用例，第二项实际写入后回执丢失，第一项的成功回执与逆操作仍可用，第二、第三项留在剪切队列。[原生 API 用例](../../../src/test/java/edu/files/Win32FileHandlesTest.java) · [适配器用例](../../../src/test/java/edu/files/NtfsFileOperationsTest.java)
- **JavaFX 真实控件 1 项。** 同一工作流打开目录、选取文本预览、用复制和粘贴按钮写入副本、用行内改名及菜单撤回并检查最新字节。批量剪切第一项成功、第二项同名冲突、第三项未执行，验证目标列表、剪切队列、计数与第一项的撤回。可通过这些步骤的完成检查确认，正常 NTFS 项目未出现额外的身份确认。[桌面用例](../../../src/test/java/edu/files/JavaFxFileOperationsTest.java)

## 本机性能对照

阶段 2.1 基线类来自 `42538b5`，两侧使用同一个基准程序和同一块 NTFS 卷的独立夹具。各场景先暖机一次，再取五次样本。表中是最小值、中位数、最大值，单位为毫秒。夹具预建和清理在测量之外。[基准程序](../../../src/test/java/edu/files/FileIdentityBenchmark.java)

| 场景 | 阶段 2.1 | 阶段 2.2 |
| --- | ---: | ---: |
| 读取 10,000 个空文件条目的 `LocalFiles.readDirectory` | 297.01 / 309.09 / 327.86 | 294.06 / 301.62 / 338.51 |
| 采集 500 个项目的原生身份 | 无原生路径 | 108.66 / 113.96 / 121.02 |
| 200 个小文件批量同卷移动，含准备请求和执行 | 149.68 / 150.99 / 157.03 | 134.64 / 147.61 / 149.34 |

身份采集本机约为每项 0.23 ms。目录读取中位数变化约 −2.4%，两组区间重叠。该时间覆盖底层目录读取，JavaFX 列表渲染、图标和缩略图未纳入测量。移动样本只覆盖小文件、同卷、热缓存，阶段 2.1 使用已确认的 NIO 路径，阶段 2.2 包含身份采集及句柄提交。两种执行路径的差值无需外推到冷缓存、网络路径和其他机器。

在 2,500 次完整身份采集前后，Win32 `GetProcessHandleCount` 读到 352 和 370。单独的原生测试在 500 次连续打开、读取和关闭后按进程整体数量检查，允许 JVM 背景线程的少量波动，并验证权限失败后的句柄可再次打开。全进程计数包含 JVM 和 JNA，长期运行或异常退出后的资源变化仍需更长时间测量。[句柄回归](../../../src/test/java/edu/files/Win32FileHandlesTest.java)

## 复现

用安装了 JDK 21 的 Windows x64 桌面会话，在项目根运行下列命令。`mvn -v` 中的 Java 版本应为 21。本地默认 `mvn test` 运行适用的文件与原生测试。第二条 Maven 命令在同一次构建中启用真实 JavaFX 测试。

```powershell
mvn -v
mvn test
mvn '-Djavafx.integration=true' package
```

在 PowerShell 7 中运行以下基准。性能夹具放在本地 NTFS 临时目录。下例从 Surefire 结果读取已经解析的测试类路径，将阶段 2.1 编译产物放在基线运行的类路径最前。两个 JVM 分别运行同一基准代码，程序退出时清理其生成的子目录。

```powershell
$bench = [IO.Directory]::CreateTempSubdirectory('javafx-file-manager-bench-').FullName
$zip = Join-Path $bench 'baseline.zip'
$baseline = Join-Path $bench 'baseline'
git archive --format=zip "--output=$zip" 42538b5a229a6844ee9d1bdde27a0234bd3cd86d
Expand-Archive -LiteralPath $zip -DestinationPath $baseline
mvn -f (Join-Path $baseline 'pom.xml') '-DskipTests' compile
$suite = ([xml](Get-Content -Raw -Encoding utf8 -LiteralPath 'target/surefire-reports/TEST-edu.files.LocalFilesTest.xml')).testsuite
$testClasspath = ($suite.properties.property | Where-Object name -eq 'java.class.path').value
$baselineClasses = Join-Path $baseline 'target/classes'
java -cp "$baselineClasses;$testClasspath" edu.files.FileIdentityBenchmark baseline $bench
java -cp $testClasspath edu.files.FileIdentityBenchmark ntfs $bench
```

实机范围还缺 Windows ARM64 原生运行、SMB、ReFS、WSL、跨卷目录移动和非 Windows 的稳定 NIO 键。未知回执通过测试替身验证协调器状态。断电、筛选驱动故障及原生调用异常退出未模拟。[安全边界](02_身份模型与安全边界.md)
