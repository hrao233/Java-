# 01 原生能力与技术选型

阶段 2.1 在 Microsoft JDK 21 和 Oracle JDK 27 上证实 Windows NIO 的 `fileKey()` 为空。该结论促成了身份采集位置的调整。阶段 2.2 用系统句柄读取 Windows 的文件和目录标识，并验证同卷名称修改是否能绑定源对象及目标目录。实验在 Windows 11 25H2、x64、NTFS 和 Microsoft OpenJDK 21.0.13.0.2 上运行。[阶段 2.1 身份记录](../02_文件操作安全/04_文件身份机制调查与设计.md)

| 候选 | 取舍 |
| --- | --- |
| JNA | Java 21 可直接运行。用少量 DLL 映射完成打开、查询、改名和关闭，单次操作可在一个 JVM 内保持句柄。采用缓存中已有的 5.17.0。 |
| JNI | 可以用 C 头文件定义结构布局，需维护原生编译、签名、平台产物和打包。此处的调用集合小，JNA 已覆盖。 |
| FFM | JDK 21 的外部函数接口需要预览选项，给 IDE、测试和应用发行引入启动约束。 |
| PowerShell | 能用于诊断和原型。逐项启动子进程增加成本，跨多次调用保存和共享句柄也更复杂。 |
| Java NIO | 平台覆盖较广。在缺少 Windows 原生能力时使用阶段 2.1 的降级规则。公开的 Windows `fileKey()` 无法提供本阶段使用的凭据。 |

| 实验路径 | 本机实测 |
| --- | --- |
| `GetFileInformationByHandleEx(FileIdInfo)` | 返回卷序列和 128 位文件 ID。硬链接共享对象 ID，同卷改名保持 ID，等内容同名替代品的 ID 不同。 |
| `SetFileInformationByHandle(FileRenameInfo)`，绝对路径 | 同卷、大小写、嵌套目录及无覆盖实验通过。目标绝对路径仍由系统重新解析。 |
| `SetFileInformationByHandle(FileRenameInfo)`，目标父目录句柄及相对名称 | Microsoft Learn 说明这种形态可用，本机带 `RootDirectory` 的实测返回 Windows 错误 87。生产不依赖这一形态。 |
| `NtSetInformationFile(FileRenameInformation)`，目标父目录句柄及相对名称 | 同卷、大小写、目录、硬链接路径及冲突实验通过。目标只有一个名称组件，ReplaceIfExists 为 false。同名冲突实测为错误 183。 |

选用 **JNA + NT 相对目录改名**。源通过 `CreateFileW(OPEN_EXISTING)` 获得包含 DELETE 权限的句柄，短期共享模式阻止其它普通句柄请求 DELETE。目标用已核对的目录句柄作为 RootDirectory，系统调用直接对这两个已打开对象执行。`CloseHandle` 在成功、失败和退出路径由 try-with-resources 调用。测试固定结构布局及当地文件系统行为，生产限定已验证的 Windows x64 本地 NTFS 条件。[Win32 映射](../../../src/main/java/edu/files/Win32FileHandles.java) · [原生回归](../../../src/test/java/edu/files/Win32FileHandlesTest.java)

官方 API 资料见 [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)、[FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info)、[Win32 FILE_RENAME_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info) 和 [NT FILE_RENAME_INFORMATION](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information)。
