# 05 跨卷移动与冲突处理设计

隔离实验在本机两个 NTFS 卷上移动一棵包含深层文本的目录。JDK 21 的路径调用返回 `DirectoryNotEmptyException`，源字节完整，正式目标缺席。随后在目标卷暂存复制，经 `Files.mismatch` 核对，再尝试发布至已占用的正式名称。系统拒绝覆盖，源对象仍在，占用者字节完整。单机实验覆盖默认冲突和常见跨卷目录失败，源清理协议仍需独立验证。

| 阶段 | 中途失败或取消时可能保留的数据 | 设计要求 |
| --- | --- | --- |
| 核查 | 源保持，目标可能已存在 | 核对源对象与父目录、目标卷、目标目录和有效名称。真实写入前检查取消。 |
| 暂存复制 | 源与局部暂存副本并存 | 分项回执，处理权限和磁盘不足。仅清理已证明属于任务的对象。 |
| 完整性验证 | 源与完整度待定的暂存副本并存 | 树清单可检查路径和类型。逐字节比对或摘要追加 O(总字节数) 的 I/O，且需要明确 ACL、备用数据流、链接和动态源语义。 |
| 无覆盖发布 | 成功时源与目标同时存在。冲突时旧目标、源和暂存可并存 | 用目标卷的目录句柄提交并记录正式目标的身份。提交结果未知时暂停后续源处理。 |
| 再验证来源 | 源或深层目录可能已经改写或换名 | 需要可信的来源对象和完整性证明。若信息不足，保留两份并报告状态。 |
| 处理来源 | 目标已发布。源端可能完全保留或需要恢复 | 候选方案为用户明确确认、源侧句柄约束的同卷隔离和系统回收。递归删除旧路径的变体缺乏本阶段所需证据。 |
| 记录最终结果 | 可能出现两份副本、暂存残留或写后回执丢失 | 对每步建回执，核查只能读路径。进程异常时由后续恢复方案处理遗留数据。 |

同名冲突目前保持无覆盖。后续的「跳过」需要独立状态和适当的剪切保留规则。「保留两者」必须由无覆盖提交决定实际副本名，并将该名称写入回执。「替换」应先核对被替换对象及目标父目录，定义可恢复的旧目标隔离，避免在 UI 确认后覆盖同名替代品。「应用到后续」复用的是策略，仍要逐项核对身份。 [实际批次状态](../../../src/main/java/edu/files/FileChanges.java)

验收至少要覆盖大目录和动态文件、源目标对象替换、磁盘空间不足、发布前取消、发布后保留两份、源端权限不足及回执丢失。每一个测试同时核对三个位置的文件及应用队列，源删除须等完整性和可恢复语义通过隔离验证。 [当前暂存与取消模型](03_复制进度与协作式取消.md)
