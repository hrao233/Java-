# 01 监听实验与技术选型

| 候选 | 适用性与代价 |
| --- | --- |
| Java NIO `WatchService` | 提供目录注册、创建、修改、删除、溢出及键的生命周期。Java 层可以使用相同的事件合并逻辑。需要自行界定提供者、远程存储和目录替换的行为。 |
| Windows `ReadDirectoryChangesW` | 可控制目录句柄、过滤掩码、缓冲区和异步完成，适合特定 Windows 行为有证据时再评估。需要自行管理缓冲区、I/O 取消与句柄释放。驱动支持错误、远程缓冲区限制和溢出仍需通过读盘恢复。 |
| 定期轮询目录状态 | 任意可枚举目录都可做定时快照。每轮需枚举和读取属性，大目录及网络往返代价高。只对比名称、大小和修改时间会漏掉同名同属性替换。 |
| 事件和轻量轮询 | 普通变化由事件触发目录重读。低频只核对目标目录身份，补父目录事件缺失或键仍有效的情况。也可对无监听提供者做轮询，但其网络超时和开销需要单独验证。 |

JDK 明确允许提供者对时序、事件次数和顺序作不同实现。溢出时，应用需要重新检查状态。Windows 原生接口同样可能丢失细节，文档要求溢出后枚举目录，远程监视还受协议和缓冲区限制。 [Java 21 WatchService](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/nio/file/WatchService.html) · [Microsoft ReadDirectoryChangesW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw)

## 隔离实验

本机使用 Windows 11 x64、Microsoft OpenJDK 21.0.13.0.2 和固定 NTFS。先用探针观察原始键和事件，再把可重复断言纳入 JUnit。实验目录、写入和重命名均在本次创建的夹具内。 [DirectoryWatcherTest](../../../src/test/java/edu/files/DirectoryWatcherTest.java)

| 操作 | 观察 | 工程影响 |
| --- | --- | --- |
| 创建、原地写入、删除 | 收到创建、修改和删除通知。一次写入可触发多次观察。 | 同一路径合并，读盘时重取属性。 |
| 改名、临时文件替换式保存 | 改名出现旧名删除和新名创建。替换还涉及临时名及目标名。 | 无需成对解析来猜测具体操作，完成后的名单由目录读取确定。 |
| 移走目录后在原位置重建 | 原目录键仍可能有效并绑定移走的对象，父目录出现原名删除和创建。 | 同时观察父目录，目录路径用原生身份重新核对。 |
| 删除重建后的目录 | 新目录键失效。 | 检测键失效，发出全量重读并尝试重新注册。 |
| 暂停消费后创建 3,000 个文件 | 一次原始探针得到 `OVERFLOW`，该事件的计数为 2,488。JUnit 过滤所有普通路径事件后仍收到第二次全量通知。 | 无须知道丢失了哪些名称，整个当前目录进入重读。 |
| ZIP 文件系统 | 创建 WatchService 抛出 `UnsupportedOperationException`。 | 报告监听不可用并验证工作线程退出。 |

首期采用 WatchService 加单目录身份复核。注册范围通过现有 `DirectoryIdentity.ntfs()` 限定在具备可验证身份的本地固定 NTFS 路径。符号链接和 Junction 路径按现有原生身份规则降级。SMB、非 NTFS 及非 Windows 平台的自动监听本机未作端到端验证，这些位置可手动刷新。目录自身是卷根时只有目录键。 [身份适配](../../../src/main/java/edu/files/NtfsFileOperations.java) · [目录身份](../../../src/main/java/edu/files/DirectoryIdentity.java)
