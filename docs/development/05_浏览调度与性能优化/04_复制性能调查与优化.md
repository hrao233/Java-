# 04 复制性能调查与优化

基于 1,000 个 4 KiB 文件的同卷 NTFS 任务，按线程启用诊断，对 Win32 路径打开、NT 相对打开、关闭、身份和属性查询、复制、ACL 读写、进度回调、目录树核对及清理计时。各段存在嵌套，发布前目录树核对的计时包含该阶段的句柄打开和身份读取。普通运行在各诊断点检查线程本地的采集状态。 [诊断定义](../../../src/main/java/edu/files/CopyDiagnostics.java) · [基准](../../../src/test/java/edu/files/Phase24IoBenchmark.java)

### 优化前诊断样本

| 项目 | 次数 | 累计时间 |
| --- | ---: | ---: |
| 路径打开与相对打开 | 1,020 / 2,003 | 33.47 / 820.37 ms |
| 关闭句柄 | 3,023 | 47.12 ms |
| 文件 ID 与属性 | 3,006 / 3,020 | 19.83 / 17.98 ms |
| 系统复制与进度回调 | 1,000 / 2,000 | 433.41 ms，回调计次数 |
| ACL 读取与写入 | 2,000 / 1,000 | 44.79 / 55.83 ms |
| 发布前目录树核对 | 1 | 815.36 ms |
| 成功后的暂存清理 | 1 | 0.09 ms |

相对打开和发布前核对是该样本中最重的开销。每次开句柄可以区分此前验证过的目录项与现在相同名称的替代品。复用跨文件的原生复制回调句柄会延长共享锁并且缺少写 ACL 所需的授权，目录批量查询 ID 则需要另行验证其与逐项句柄核对等价。本阶段仅复用真实可保持的输入缓冲和省掉普通叶子未消费的目录属性查询。

- **ACL 缓冲按一次暂存复制复用。** 先向固定容量缓冲读取当前来源的完整 ACL、所有者和组。Windows 报告缓冲不足时按需求扩容再读。每个文件仍有独立的安全描述符和写入。测试复制超过初始容量的 ACL，再检查相邻普通文件保留各自规则。 [原生适配](../../../src/main/java/edu/files/Win32FileHandles.java) · [原生回归](../../../src/test/java/edu/files/StagedCopyTest.java)
- **发布核对与安全清理保有独立证据。** 普通文件仍在属性处理前与发布前读取 ID。目录仍检查目录类型、重解析点和整棵暂存树范围。替换不会获得原来的 ID，最后一次无覆盖发布仍由内核裁决。 [暂存核对](../../../src/main/java/edu/files/StagedCopy.java)

优化后，诊断样本的 ACL 读取次数由 2,000 降至 1,000，属性查询由 3,020 降至 1,020。相对打开仍是 2,003 次，文件 ID 仍是 3,006 次。对应的 ACL 读取累计从 44.79 ms 到 23.72 ms，单独属性查询从 17.98 ms 到 6.36 ms。整体对照使用未开启诊断的耗时。 [实测结果](05_回归测试与性能验证.md)
