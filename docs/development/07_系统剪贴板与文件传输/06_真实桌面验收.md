验收人确认 A1 至 G 均符合预期，其中 C 在修复后重新通过。只读校验覆盖 12 个目录。

## C 的修复

外部剪切进入拒绝分支后，旧版将结果放在状态栏。列表请求进行时可能跳过状态文字更新，后续列表刷新也会更新状态栏。修复复用现有信息对话框，在明确发起外部剪切粘贴时提示回到来源使用「复制」。拒绝仍发生在创建文件任务之前。

跨应用剪切表示移动。来源端和接收端需要约定哪一方移动或清理源项目，以及如何报告部分成功、失败和未完成的项目。同窗口剪切可以沿用发起时获取的文件身份和本窗口任务结果。阶段 2.6 在跨应用场景支持复制，尝试粘贴外部剪切时保留源项目并明确提示用户改用复制。 [会话与文件安全](02_会话与文件安全.md) · [Windows 协议](01_Windows协议与技术选型.md)

JavaFX 回归用例验证所属窗口的拒绝对话框、改用复制的提示、粘贴禁用状态、源内容、目标为空，以及原剪贴板版本保留。新增断言在修复前因对话框缺失而失败。 [实现](../../../src/main/java/edu/files/FileManagerApp.java) · [JavaFX 回归](../../../src/test/java/edu/files/JavaFxFileOperationsTest.java)
