# 04 回归与性能

Windows 11 x64、Microsoft OpenJDK 21.0.13.0.2、Maven 3.10.0、JavaFX 21.0.6 和本地 NTFS。普通套件使用测试替身、真实文件夹和独立窗口，系统剪贴板实验由单独脚本启动。具名窗口站创建返回 Win32 错误 5，匿名非交互窗口站可用。子进程和原生调用通过窗口站名称确认隔离，开始前验证它的剪贴板为空。所有文件变化限制在新建的临时夹具。

| 版本和命令 | 发现 | 通过 | 跳过 | 失败 |
| --- | ---: | ---: | ---: | ---: |
| 阶段 2.5 `mvn test` | 87 | 82 | 5 | 0 |
| 阶段 2.5 启用 JavaFX 的 `package` | 87 | 86 | 1 | 0 |
| 阶段 2.6 `mvn test` | 101 | 92 | 9 | 0 |
| 阶段 2.6 启用 JavaFX 的 `package` | 101 | 100 | 1 | 0 |

本阶段新增 14 项 JUnit 用例，其中 8 项检查协议和会话，2 项使用 Windows Shell 的编码或解码，4 项验证 JavaFX 交互。默认构建跳过 8 项桌面用例，两种配置都跳过本机缺少 NIO 文件键的 1 项旧用例。真实窗口回归核对剪切标记、覆盖竞态、复制路径、文本控件事件、部分成功、拒绝外部 MOVE 和同名替代品。Mermaid 11.12.2 已通过 Chrome 158 实际渲染，图的 SVG 显示尺寸为 1074 × 665。

## 性能与资源

一次真实 JavaFX 测样中，测试替身更换剪贴板至粘贴按钮启用用时 205.73 ms。真实 NTFS 目录发生无关变化至剪切标记复核完成用时 205.51 ms，计入目录监听合并和 JavaFX 应用更新。两项均为端到端样本，分别测量剪贴板状态投影和自动刷新后的状态恢复。

| 同机原生实验 | 发布文件剪贴板 | 读取并解码 | 读取有效源身份 |
| --- | ---: | ---: | ---: |
| 1 个文件，5 次中位数 | 11.80 ms | 0.90 ms | 1.03 ms |
| 1,000 个文件，3 次中位数 | 1,751.02 ms | 5.34 ms | 256.67 ms |

每组先暖机一次。发布含 Shell 项目标识、编码、剪贴板锁和内存移交。身份采集单独计时，包括文件属性读取和本地 NTFS 身份获取。千项发布的等待量级约 1.75 秒，工作发生在剪贴板线程。另一个进程持锁时，实际等待至报告占用用时 108.00 ms。

原生测试覆盖旧剪切会话失去版本后尝试清理，以及实际保持新发布。过程采样的进程句柄为初始 341、峰值 456、最终 439，进程私有内存为 362.8、379.5、374.2 MiB。数据覆盖一次较短测量和 JVM、JNA、Windows Shell 的综合资源，常驻增长原因和长期走势仍待分析。运行结束时隔离剪贴板的格式数为 0。 [性能与锁竞争用例](../../../src/test/java/edu/files/Phase26ClipboardProbe.java)

## 复现

```powershell
mvn -v
mvn test
mvn '-Djavafx.integration=true' package
mvn '-Djavafx.integration=true' '-Djavafx.captureClipboard=true' '-Dtest=JavaFxFileOperationsTest' test
./src/test/windows/clipboard-integration.ps1
./src/test/windows/clipboard-integration.ps1 -MeasureOnly
```

最后一条命令从前面 Maven 报告取得类路径，另开匿名非交互窗口站和测试桌面。启用了截图时，JavaFX 输出带 `PHASE26_SCREENSHOT` 的生成路径。脚本生成的日志和互动截图位于本次临时夹具。 [隔离运行器](../../../src/test/windows/clipboard-integration.ps1) · [原生协议测试](../../../src/test/java/edu/files/WindowsClipboardFormatTest.java) · [JavaFX 回归](../../../src/test/java/edu/files/JavaFxFileOperationsTest.java)
