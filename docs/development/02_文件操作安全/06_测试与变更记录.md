# 06 测试与变更记录

日期为 2026-11-26（UTC+8）。Windows 11 25H2、NTFS、Apache Maven 3.10.0、JavaFX 21.0.6。真 JDK 21 使用 Microsoft `21.0.13.0.2+1-LTS`，对照使用 Oracle `27+35-2325`。编译目标是 `release 21`。Maven 构建在临时源码副本运行，仓库内测试仍通过标准 `mvn test` 入口执行。

| 执行 | 结果 |

基线的 6 个失败分别是深层目录副本被撤销移走、同大小同时间的文件副本被撤销移走、同大小同时间的新建文件被永久删除、撤销移动搬走同名替代品、内部剪贴板复制替代品、批量运行时异常使已写入前缀无结果。隔离基线只为 `PasteItem` 注入假回收，默认的旧判断仍执行。修复后同样的文件存在性、内容和批次断言通过，并增加明确的拒绝/失败状态检查。实验资料位于本机 `%TEMP%\javafx-safety-21-3fzryk1v.03b`，包括 `red.log`、`green21.log`、`green27.log` 和 `fx21.log`。见 [回归测试体系](01_回归测试体系.md)。

JavaFX 使用真实 `Stage`、控件与事件。窗口透明，Preferences 在内存，所有写入用夹具。通过的检查为启动、目录打开及历史、递归搜索、文本与图片预览、行内改名、取消及确认复制和撤销被拒绝、剪切和 Ctrl+Z 拒绝无凭据撤回、批量剪切部分写入后的列表和余项、剪贴板同名替代拒绝、手动刷新、图标与图库。批量场景有两个目录，第一项成功后正好出现 `a.txt` 和已有的 `b.txt`，原目录 `b.txt` 与 `c.txt` 留在剪切队列且内容完整。通过的回收适配测试使用夹具替身。

## 已知验证边界

- 正常复制、同目录副本和发布前的失败路径没有在用例检查中留下 `.file-manager-*`。进程崩溃、断电、暂存清理权限被夺走、磁盘满和网络故障没有验证。
- Windows 公共属性 API 的键为空，稳定键提供者上的正向成功撤回用例在两个 Windows JVM 都跳过。无键路径和受控的同批逆操作已验证。Linux、macOS 以及其它 Windows 卷、权限和提供者仍待测。
- 真实 OS 回收与恢复、格式化及断开网络驱动器未运行。跨卷实际状态以原审查 S17 为历史证据，本阶段沿用平台移动能力与无覆盖原则。文件身份、竞争窗口和未来候选见 [专项设计](04_文件身份机制调查与设计.md)。
