# 02 危险撤销修复

原 `PasteItem.undo` 比较复制结果与当前目标的根 `Entry`，相等就回收。根目录的快照不包含深层文件。普通文件也能在保持长度和修改时间的情况下改变内容。原 `NewItems.Created.undo` 直接删除对象，有些提供者的新旧 `fileKey` 均为空，剩余属性仍无法证明数据未被改写。三个用例都在修改前复现，被移除的是夹具，回收走测试替身。见 [原审查 F01](../../audit/06_文件操作与数据安全.md) 和 [测试记录](06_测试与变更记录.md)。

| 候选 | 时间及存储 | 安全性、平台依赖和体验 |
| --- | --- | --- |
| 拒绝复制目录的自动撤销 | 每项 O(1)，无需扫描和保存目录数据 | 这条撤销路径没有文件系统修改，也没有验证后删除的竞态。Windows、Unix 可使用相同规则。用户需自行处理副本。相同问题的普通副本、新建文件和目录也采用此规则。 |
| 保存树的路径和元数据快照 | 首次和撤销前各 O(n) 或更多 I/O，O(n) 状态，n 为条目数 | 可以发现许多新增、移除和时间变化。无法排除等长等时间的修改、文件身份替换、未枚举内容以及扫描后改动。长树、权限和链接影响完整性。 |
| 保存树身份和内容完整性 | 枚举 O(n)，读字节 O(b)，记录摘要及身份 O(n)。b 为内容总字节数 | 可覆盖更多变化，仍要明确 NTFS 数据流、ACL、链接、硬链接和打开写入的范围。ID 可重用，读取和回收之间仍有窗口。大型本地目录或网络目录会有额外成本。 |
| 参与操作的句柄和可回收暂存 | 成本随打开的对象、临时目录和验证策略增长 | 可研究用句柄提高手段可靠性，或把经过确认的项目移到可恢复位置。需要处理跨卷、活动文件、句柄权限、隔离区恢复和用户编辑。是否允许重命名后隔离也需产品决定。 |

本阶段选择第一种，并扩大到所有应用生成的副本与新建项。`FileChanges.transfer` 复制成功后记下实际目标位置，撤销记录只生成中文拒绝理由。`NewItems.Created` 保留新建条目的属性快照供后续命名，直接删除的逆方法已移除。普通重命名和新建后的改名共用写入检查。提供者可验证身份时，撤回一次改名只恢复名称。见 [复制及撤销工厂](../../../src/main/java/edu/files/FileChanges.java#L86)、[新建类型](../../../src/main/java/edu/files/NewItems.java#L37) 和 [应用调用点](../../../src/main/java/edu/files/FileManagerApp.java#L1560)。

移动或改名有另一条路径。正向操作确认来源，为已知身份读取原父目录，记实际目标，比较前后身份。逆向在搬回前再次检查原父目录及当前目标，并坚持无覆盖。无法取得足够身份的操作只产生拒绝记录。本机 Windows 正常前向移动仍能完成，但其逆向会拒绝。已验证缺失目标和占用原名时保留数据。提供者能给出有效键时才验证有身份的撤回分支，NIO 的检查与执行仍是分开的。见 [reverseMove](../../../src/main/java/edu/files/FileChanges.java#L129) 和 [身份机制](04_文件身份机制调查与设计.md)。

拒绝不会显示为撤销成功。批次遍历可以跳过已明确禁用的逆操作，继续执行其它逆操作。遇到暂时失败或结果未知时停止，并保存失败项及其余项。测试用一个独立的安全逆操作验证它在前面一项拒绝后仍执行，避免拿 Windows 提供者注定不支持的分支冒充成功。见 [拒绝与同批撤回测试](../../../src/test/java/edu/files/FileSafetyTest.java#L282)。
