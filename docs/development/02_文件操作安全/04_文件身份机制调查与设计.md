# 04 文件身份机制调查与设计

本机 NTFS 上，Microsoft JDK `21.0.13.0.2+1-LTS` 和 Oracle JDK `27+35-2325` 的 `Files.readAttributes` 返回的 `BasicFileAttributes.fileKey()` 与 `DosFileAttributes.fileKey()` 对普通文件、硬链接、改名后的文件、同名等字节替代品和目录均为 `null`。两套 JDK 各以默认设置和 `-Dsun.nio.fs.ensureAccurateMetadata=true` 启动，结果一致。对应 JDK 自带的 `lib/src.zip` 中，WindowsFileAttributes 的 `fileKey()` 分别在第 403、474 行直接返回 `null`。属性查询能用句柄，JDK 的公开 NIO 方法在这两个版本上仍未返回这些内部键。`isSameFile` 的内部实现可以比较卷序列和文件索引，提供者还可能在两条路径相等时短路。所以验证需要一个独立引用，不能等改名前的原路径消失后，再用同一字符串推断前后对象。见 [Java 文件属性 API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/nio/file/attribute/BasicFileAttributes.html#fileKey())。

| 实验 | JDK 21 | JDK 27 | Win32 只读查询 |
| --- | --- | --- | --- |
| 普通文件与硬链接 | 键均为空，`isSameFile=true` | 同左 | 卷序列和 128 位 ID 相同 |
| 同卷改名后对照独立硬链接 | `isSameFile=true`，键仍为空 | 同左 | ID 与原名时相同 |
| 同名、同字节替代品对照原硬链接 | `isSameFile=false`，键仍为空 | 同左 | ID 不同 |
| 目录属性 | Basic、DOS 键均为空 | 同左 | 能取得目录的 ID |
| 打开准确元数据选项 | 仍为空 | 仍为空 | 此栏不依赖 JVM 开关 |

Win32 实验用 `CreateFileW` 以属性读取权限打开夹具，设置 `FILE_FLAG_BACKUP_SEMANTICS` 允许目录，使用 `FILE_FLAG_OPEN_REPARSE_POINT` 明确打开末端重解析对象，再调用 `GetFileInformationByHandleEx(FileIdInfo)`。实验观察到的 ID 对象只在相应卷和实验期间有效。生产程序目前没有调用这套 API。见 [CreateFileW](https://learn.microsoft.com/windows/win32/api/fileapi/nf-fileapi-createfilew)、[GetFileInformationByHandleEx](https://learn.microsoft.com/windows/win32/api/fileapi/nf-fileapi-getfileinformationbyhandleex) 和 [FILE_ID_INFO](https://learn.microsoft.com/windows/win32/api/winbase/ns-winbase-file_id_info)。

## 下一阶段要分别记录什么

| 意图或事实 | 建议字段和校验点 |
| --- | --- |
| 用户请求的对象 | 请求路径、选中时间、对象类型、是否链接、可用的身份凭据，以及路径确认范围 |
| 执行时的对象 | 再打开或核对出的来源句柄、父目录和对象身份。区分原件、替代、缺失、无权限和无法识别 |
| 实际产生的目标 | 发布后的实际目录项和名称，例如同目录复制的副本名。按适用规则确认身份，跨卷新对象须与来源关联 |
| 操作结果和完整性 | 每项状态、错误、读到的字节或可选摘要、观测位置。哈希只能描述读取到的内容 |
| 撤销的前置条件 | 原父目录、回退目标、写后对象身份、是否需要内容快照。不能判断时保留数据与原因 |

- **路径、对象、内容。** 路径定位目录项。多个硬链接能指向同一个对象，删除或重命名某一个名称会改变不同目录项。两份相同字节可属于不同对象，同一对象也可被原地改写。对象和父目录的身份都需要考虑。
- **FILE ID 的范围。** 文件删除后 ID 可能被重用。用卷范围和验证时刻约束，必要时保留句柄绑定对象。创建时间可以当附加拒绝条件，时间和哈希不能单独作为身份。长期持久化若要跨进程使用身份，还要定义重启、卷重挂载和 ID 重用行为。
- **链接与网络。** 符号链接和 Junction 的自身身份、目标身份与祖先解析需分别处理。`OPEN_REPARSE_POINT` 只约束末端，祖先目录仍要单独处理。SMB、WSL、FAT/ReFS、云占位文件与长路径需独立验证，还要约定无权限、共享模式和不支持 API 的处理。
- **竞争窗口。** 当前 NIO 检查完成后，再通过路径执行。另一进程仍可能在这之间换名、换父目录或改变内容。Win32 查询完再关闭句柄、用 Java 路径操作，也存在相同窗口。可研究用打开的对象句柄提交改名，明确权限、祖先、无覆盖和句柄共享策略。Shell 回收按路径的语义需要独立设计。见 [SetFileInformationByHandle](https://learn.microsoft.com/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)。

本阶段在有对象键时比较键、类型和创建时间。键无法取得时，复制、移动、改名、回收需要用户确认对这些路径当前的项目执行，并在写入前核对大小、时间和类型。可检测的不一致会拒绝。同名同元数据替换在无身份的平台仍可能无法识别，且确认后仍可能发生竞争。自动撤销没有路径确认后备。见 [LocalFiles.Entry 与核对](../../../src/main/java/edu/files/LocalFiles.java#L59) 和 [中文确认](../../../src/main/java/edu/files/FileManagerApp.java#L1645)。
